1　引言
1.1　编写目的
本文档为《天津地方农特产推广服务平台》的需求规格说明书，用于明确系统的建设背景、用户角色、功能需求与非功能需求，作为小组后续开展数据库设计、接口设计、编码实现与测试验收的依据，同时作为课程设计验收时功能完整性的对照标准。本文档的预期读者为本小组全体成员及指导教师。
1.2　项目背景
天津地处华北平原东北部，农业资源丰富，拥有小站稻、沙窝萝卜、茶淀葡萄、盘山磨盘柿、七里海河蟹、静海金丝小枣等一批具有地方特色的农副产品；同时在蓟州、西青、静海、宁河等区分布着大量果园与有机蔬菜农场，每年吸引众多市民前往采摘体验。
当前天津本地农特产与农园采摘资源主要存在以下问题：
销售渠道传统单一，多数农户缺乏线上展示与销售能力，优质农特产缺少品牌化推广出口；
采摘体验资源信息分散，消费者难以一站式获取周边农园的位置、采摘品种、价格与营业信息；
分散经营的农户与消费者之间缺乏统一的信任背书与对接平台。
为此，本课程设计拟开发“天津地方农特产推广服务平台”，以微信小程序作为用户端、Web系统作为管理端，集“农特产线上商城、农园采摘体验预约、内容推广”于一体。平台的农园体验预约功能不局限于果园采摘，按照指导教师意见同时覆盖有机蔬菜农场的采摘与农事体验，实现“果园＋菜园”双类型的统一预约服务，从而满足天津本地消费者购买优质农特产与近郊休闲采摘的双重需求。

2　项目概述
2.1　项目目标
总体目标：面向天津本地消费者与农业经营者，建设一个集农特产线上商城、农园采摘体验预约与内容推广于一体的本地化服务平台，实现“看得到、摘得到、买得到、管得住”。
具体目标如下：
为本地农户与合作社提供商品上架、农园信息发布的线上渠道，降低线上经营门槛；
为消费者提供基于地理位置的周边农园发现与在线预约采摘能力，果园与有机蔬菜农场两类农园统一支持；
提供覆盖浏览、下单、支付、发货、收货、评价的完整线上购物能力；
为平台方提供商家入驻审核、内容管理与经营数据统计能力；
5人小组分工协作，按期交付满足本文档验收标准的可演示系统。
2.2　用户角色与权限
平台共设四类用户角色，各角色的定位与权限如下表所示。
表2-1　用户角色与权限
| 角色 | 角色说明 | 主要权限 |
| 游客 | 未登录或未注册的访问者 | 浏览首页、商品列表与详情、农园列表与详情；不可下单、预约、收藏与评价 |
| 注册用户 | 通过微信授权注册的消费者 | 游客全部权限；下单与模拟支付、预约采摘、收货地址管理、收藏、评价、意见反馈 |
| 商家 | 经平台审核通过的农户、合作社或农园经营者 | 商家信息维护、商品上架管理、农园与采摘项目发布、预约通知查看与到园确认、订单发货、经营统计 |
| 平台管理员 | 平台运营方人员 | 商家入驻审核、用户管理、内容管理、商品巡检、订单与预约总览、数据统计、系统管理 |
2.3　核心业务流程概述
（1）农园采摘预约流程。用户进入“农园体验”模块后，用户以列表形式浏览果园与有机蔬菜农场，支持按区县、农园类型、采摘品种等条件筛选。用户进入农园详情页，查看当季可采摘项目及其价格、计价方式与可约场次，选择日期、场次与人数后提交预约；系统校验场次库存，用户完成模拟支付后预约单生效，商家端随即收到对应的果园或蔬菜园被预约的通知（含预约人、联系电话、预约日期与场次、人数）。用户按约到园，由商家根据其预留的手机号等信息进行现场确认，完成采摘体验后可对农园进行评价。
（2）商城购物流程。用户通过分类浏览或搜索找到目标农特产，进入商品详情选择规格与数量，可加入购物车合并结算，也可立即购买。提交订单时选择收货地址，完成模拟支付后订单进入待发货状态；商家在管理端查看订单并发货，用户确认收货后订单完成，并可对商品进行图文评价。
2.4　运行环境
服务端：Linux或Windows服务器，JDK 1.8及以上，MySQL 8.0，Redis；
用户端：iOS／Android微信客户端内运行的小程序；
管理端：Chrome、Edge等现代桌面浏览器；
开发工具：IntelliJ IDEA、VS Code、Navicat、微信开发者工具、Git。
2.5　设计约束
后端采用Spring Boot框架；
用户端以微信小程序形式交付；
支付功能采用模拟支付，不接入真实支付渠道；
农园位置以文字地址形式展示；
3　功能需求
3.0　功能结构总览
平台整体划分为六大功能模块，覆盖用户端（小程序）与管理端（Web）两侧，模块划分及归属如下表所示。
表3-1　功能模块总览
| 编号 | 功能模块 | 使用端 | 功能简述 |
| FR-01 | 首页模块 | 小程序 | 平台门面与流量入口，聚合推广内容并提供各模块导航 |
| FR-02 | 农园体验与采摘预约模块 | 小程序／管理端 | 果园与有机蔬菜农场的发现、筛选与在线预约 |
| FR-03 | 商城购物模块 | 小程序／管理端 | 农特产浏览、下单、支付与订单管理 |
| FR-04 | 个人中心模块 | 小程序 | 个人信息、收货地址、我的预约、我的订单、收藏等管理 |
| FR-05 | 商家工作台 | 管理端 | 商家入驻与商品、农园、预约、订单经营管理 |
| FR-06 | 平台管理 | 管理端 | 商家审核、用户与内容管理、数据统计 |
本章功能点优先级说明：高＝本期必须实现；中＝时间允许应实现；低＝拓展项，可不实现。
3.1　首页模块（FR-01）
首页是平台的门面与流量分发入口，承担天津本地特色农特产与农园体验的推广职责，需在有限的篇幅内向用户传达“当季有什么、各区县有什么、平台主推什么”。
表3-2　首页模块功能点
| 编号 | 功能点 | 功能说明 | 优先级 |
| FR-01-01 | 轮播图 | 首页顶部展示运营轮播图（平台活动、当季主推、农园推荐等），支持点击跳转对应商品、农园或公告页面 | 高 |
| FR-01-02 | 搜索 | 提供关键词搜索，同时匹配商品名称与农园名称，展示聚合搜索结果 | 高 |
| FR-01-03 | 分类导航 | 金刚区展示一级分类入口：时令水果、有机蔬菜、粮油米面、禽蛋副食、干货特产、农园采摘等 | 高 |
| FR-01-04 | 推荐 | 按后台管理设置推荐当季农特产（如秋季茶淀葡萄、冬季沙窝萝卜） | 中 |
| FR-01-05 | 农园入口 | 展示农园卡片，点击进入农园体验模块 | 高 |
| FR-01-06 | 公告栏 | 滚动展示平台公告与活动通知 | 低 |
| FR-01-07 | 下拉刷新 | 首页支持下拉刷新最新数据 | 中 |
3.2　农园体验与采摘预约模块（FR-02）
本模块是平台的特色功能模块，整合天津周边果园与有机蔬菜农场两类农园资源，提供农园信息浏览与在线预约采摘服务。按照指导教师意见，本模块不局限于果园采摘，需同时覆盖有机蔬菜农场的采摘与农事体验；两类农园在预约流程上统一，在类型筛选与采摘项目信息上区分。
表3-3　农园体验与采摘预约模块功能点
| 编号 | 功能点 | 功能说明 | 优先级 |
| FR-02-01 | 农园列表 | 以卡片形式展示农园：封面图、名称、类型标签（果园／有机蔬菜农场）、评分、所在区县、人均价格 | 高 |
| FR-02-02 | 地址复制 | 农园详情中的地址支持一键复制，便于用户自行前往 | 高 |
| FR-02-03 | 区县选择 | 支持手动选择区县浏览对应农园 | 高 |
| FR-02-04 | 筛选排序 | 支持按农园类型（全部／果园／有机蔬菜农场）、采摘品种、人均价格、评分进行筛选与排序 | 高 |
| FR-02-05 | 农园详情 | 展示农园地址、营业时间、联系电话（可一键拨打）、图文简介、地址一键复制及当季可采摘项目列表 | 高 |
| FR-02-06 | 采摘项目详情 | 展示项目品种名称（如红富士苹果采摘、有机草莓采摘）、当季时间、计价方式（按人头门票／按采摘重量）、价格与剩余库存 | 高 |
| FR-02-07 | 在线预约 | 用户选择预约日期、场次（上午／下午）、人数后提交预约，系统校验场次库存并锁定 | 高 |
| FR-02-08 | 预约单与商家通知 | 预约支付成功后生成预约单（状态：待支付／待使用／已使用／已取消／已过期），并向商家端推送对应的果园或蔬菜园预约通知（含预约人、联系电话、日期场次与人数） | 高 |
| FR-02-09 | 我的预约 | 用户查看预约列表与详情，在规定时间内可取消预约 | 高 |
| FR-02-10 | 到园确认 | 用户到场后报出预留手机号等信息，商家在预约列表中核对并现场确认，预约单状态更新为已使用 | 高 |
| FR-02-11 | 农园信息维护 | 商家在管理端维护农园基础信息、采摘项目、场次时间与库存 | 高 |
| FR-02-12 | 采摘评价 | 已使用（已到园确认）的预约可对农园进行星级评分与文字评价 | 中 |
| FR-02-13 | 交通指引 | 商家可填写农园交通指引（公交路线、自驾提示等），在农园详情页展示 | 中 |
| FR-02-14 | 农园推荐 | 根据用户历史预约与浏览偏好推荐农园（拓展项） | 低 |

3.6　平台管理端（FR-06）
平台管理端面向平台管理员，保障平台内容质量与运营秩序，提供审核、管理与统计能力。

4　非功能需求
4.1　性能需求
小程序首页首屏加载时间不超过3秒（正常网络环境）；
常规查询接口平均响应时间不超过500毫秒，复杂统计接口不超过2秒；
支持不少于100的并发在线用户（课程演示规模）；
演示数据规模：商品不少于200条、农园不少于30个，并预置一定量的订单与预约数据，用于展示列表分页与统计图表效果。
4.2　安全需求
用户密码采用BCrypt等单向加密算法存储，明文不落库；
全部业务接口基于JWT进行登录态校验，用户、商家、管理员接口按角色隔离；
使用MyBatis预编译与参数校验防止SQL注入，敏感字符统一转义；
关键操作（审核、封禁、退款等）记录操作日志，便于追溯；
手机号等敏感信息在列表展示时部分脱敏。
4.3　易用性需求
小程序界面符合微信小程序设计规范，主要功能从首页起不超过3次点击可达；
预约与下单流程分步引导，每一步均有明确的错误提示与引导文案；
管理端表格、表单、弹窗采用Element Plus标准交互，降低使用学习成本。
4.4　兼容性需求
用户端适配iOS与Android主流机型及主流微信版本；
管理端兼容Chrome、Edge浏览器。
4.5　可维护性与可扩展性
前后端分离，接口遵循RESTful风格，统一返回结构（code／msg／data）；
后端按Controller－Service－Mapper分层，模块间低耦合；
使用Git进行版本管理，制定统一的分支与提交规范；
预留农园类型、商品分类等字典配置能力，便于后续扩展（如新增农家乐类型）。
5　数据需求概述
5.1　核心数据实体
系统核心数据实体及其关键字段如下表所示，详细字段设计在数据库设计文档中另行给出。
表5-1　核心数据实体
| 数据实体 | 说明 | 关键字段（示例） |
| 用户（user） | 平台注册用户 | id、openid、昵称、头像、手机号、状态 |

| 采摘项目（picking_project） | 农园的可预约采摘内容 | id、farm_id、品种名称、当季起止时间、计价方式、价格、场次、库存、状态 |

| 轮播图（banner） | 首页运营位 | id、图片、跳转类型与参数、排序、状态 |
| 公告（notice） | 平台公告 | id、标题、内容、发布时间、状态 |
5.2　核心实体关系说明
系统核心实体关系概述如下：一个商家可上架多个商品，并可维护一个农园（果园或有机蔬菜农场，非必填）；一个农园下包含多个采摘项目；一个用户可创建多条收货地址、多个预约单与多个订单。每个预约单关联一个采摘项目，并记录预约日期、场次与人数；每个订单包含多条订单明细，并快照下单时的收货地址与商品价格信息；评价实体通过“关联类型＋关联ID”的通用设计，同时支持商品评价与农园评价。
6　系统技术架构概述
6.1　总体架构
系统采用前后端分离架构，整体分为三层。用户端为微信小程序，基于uni-app框架开发，为消费者提供首页、农园体验预约、商城购物与个人中心等功能；管理端为基于Vue 3与Element Plus的Web系统，商家与平台管理员以不同角色登录，根据角色展示不同的功能菜单，涵盖商品管理、农园管理、预约通知与到园确认、平台审核与数据统计等功能；服务端为Spring Boot单体应用，对外提供统一的RESTful API，使用MySQL存储业务数据，Redis缓存登录态与热点数据。
6.2　技术选型
表6-1　技术选型
| 层次 | 技术选型 | 说明 |
| 后端框架 | Spring Boot 2.7 | 课程要求的核心框架，快速构建RESTful服务 |
| ORM框架 | MyBatis-Plus | 简化单表CRUD，内置分页插件 |
| 数据库 | MySQL 8.0 | 业务数据存储 |
| 缓存 | Redis | 验证码、登录Token与热点数据缓存 |
| 认证鉴权 | JWT | 前后端分离下的无状态登录态管理 |
| 用户端 | uni-app（发布为微信小程序） | 一套代码多端发布，与小组技术栈统一 |
| 管理端 | Vue 3 ＋ Element Plus ＋ Axios | 标准后台管理界面 |
| 部署环境 | Nginx ＋ 云服务器／局域网 | 课程演示部署 |
